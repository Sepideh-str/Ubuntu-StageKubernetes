# Configure Ubuntu to Trust an Internal CA

## Purpose

Configure an Ubuntu server to trust certificates issued by the company's internal Certificate Authority (CA), so HTTPS connections to internal services work without certificate trust errors.

## Certificate Identification

The certificate initially provided was:

```text
public.crt
```

After inspecting it with OpenSSL:

```bash
openssl x509 -in /tmp/public.crt -text -noout
```

it was identified as a **server certificate**, not the CA certificate.

Key fields:

```text
Issuer:  CN=CrouseCA
Subject: CN=*.crouseco.com
```

This means:

```text
CrouseCA
   |
   | issued
   v
*.crouseco.com
```

## Install the Certificate

The `public.crt` certificate was copied to Ubuntu's trusted certificate directory:

```bash
sudo cp /tmp/public.crt /usr/local/share/ca-certificates/public.crt
```

Then the system certificate store was updated:

```bash
sudo update-ca-certificates
```

## Verification

The internal repository was tested using:

```bash
curl https://repository.crouseco.com
```

The connection succeeded without a certificate error.

## Note

For a standard PKI configuration, the preferred trust anchor is the **CA certificate** (`CrouseCA`), rather than the individual server certificate (`public.crt`).

This document describes the configuration performed on the server. Sensitive company-specific names, hostnames, and internal details should be removed or replaced before publishing externally.
