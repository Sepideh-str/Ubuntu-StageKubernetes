# Kubernetes Node Host Configuration

The Kubernetes cluster uses static host mappings to provide consistent hostname resolution between all cluster nodes.

All Kubernetes nodes should contain the same `/etc/hosts` entries.

## Node Configuration

Edit the hosts file:

```bash
sudo vi /etc/hosts
```

Add the following entries:

```text
172.25.3.194   Stage-MasterF1
172.25.3.195   Stage-MasterF2
172.25.3.196   Stage-MasterF3
172.25.3.197   Stage-WorkerF1
172.25.3.198   Stage-WorkerF2
172.25.9.114   Stage-WorkerB1
172.25.9.115   Stage-WorkerB2
172.25.25.18  Stage-WorkerD1
172.25.25.19  Stage-WorkerD2
```

## Cluster Layout

The nodes are distributed across three network zones:

| Zone     | Nodes                                                                          |
| -------- | ------------------------------------------------------------------------------ |
| FRONTEND | Stage-MasterF1, Stage-MasterF2, Stage-MasterF3, Stage-WorkerF1, Stage-WorkerF2 |
| BACKEND  | Stage-WorkerB1, Stage-WorkerB2                                                 |
| DMZ      | Stage-WorkerD1, Stage-WorkerD2                                                 |

## Verify Host Resolution

After updating `/etc/hosts`, verify that the hostnames resolve correctly:

```bash
getent hosts Stage-MasterF2
getent hosts Stage-WorkerF1
getent hosts Stage-WorkerB1
getent hosts Stage-WorkerD1
```

Expected output should contain the corresponding IP address for each hostname.

For example:

```text
172.25.3.195   Stage-MasterF2
```

Connectivity can also be tested with:

```bash
ping -c 2 Stage-MasterF2
```

Repeat the configuration on **all Kubernetes nodes** so that every node has the same cluster host mappings.

## Result

All Kubernetes nodes have static hostname resolution for the cluster nodes.

This provides consistent node-to-node hostname resolution before the Kubernetes components are installed.
