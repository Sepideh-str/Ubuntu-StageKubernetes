# Ubuntu Terminal — systemd OSC Context Issue

## Problem

The Ubuntu terminal was displaying systemd metadata such as:

```text
machineid=...
user=user
hostname=Stage-MasterF1
bootid=...
type=shell
cwd=/home/user
```

instead of showing only the normal shell prompt.

## Cause

Ubuntu's systemd provides a shell integration script:

```text
/etc/profile.d/80-systemd-osc-context.sh
```

This script sends terminal session information using **OSC 3008 escape sequences**.

The SSH terminal did not correctly interpret these sequences, so the metadata was displayed as text.

The file was a symlink to:

```text
/usr/lib/systemd/profile.d/80-systemd-osc-context.sh
```

## Resolution

### 1. Log in as root

First, connect to the server and log in as the `root` user.

All commands in this section should be executed from the **root shell**.

You can verify the current user with:

```bash
whoami
```

Expected output:

```text
root
```

### 2. Disable the profile script

Rename the script instead of deleting it:

```bash
mv /etc/profile.d/80-systemd-osc-context.sh /etc/profile.d/80-systemd-osc-context.sh.disabled
```

### 3. Reconnect to the server

Disconnect from the current SSH session and reconnect.

The terminal should now return to the normal shell prompt, for example:

```text
user@Stage-MasterF1:~$
```

## Why Rename Instead of Delete?

Renaming the file is safer than deleting it because the original configuration can be restored if needed.

To restore the original file, log in as `root` and run:

```bash
mv /etc/profile.d/80-systemd-osc-context.sh.disabled \
   /etc/profile.d/80-systemd-osc-context.sh
```

Then disconnect and reconnect to the SSH session.

## Summary

The issue was caused by a **systemd terminal-context integration** that sends OSC 3008 metadata. The SSH terminal displayed the escape sequences as text instead of interpreting them.

The problem was not related to:

* Bash `PS1`
* Kubernetes
* SSH authentication
* Server networking

The systemd OSC context script was disabled by renaming it, which restored a clean terminal prompt.

> **Note:** The commands in this document are intended to be executed after logging in as the `root` user. Therefore, `sudo` is not required.
