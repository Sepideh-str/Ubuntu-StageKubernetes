# Host Firewall Configuration

The Kubernetes cluster uses network-level firewall controls to manage communication between the Kubernetes nodes and the surrounding infrastructure.

The AlmaLinux configuration used `firewalld`. Ubuntu 26.04 does not use `firewalld` by default, so the Ubuntu node configuration is handled differently.

## 1. Check UFW Status

Check whether Ubuntu's uncomplicated firewall (UFW) is active:

```bash
sudo ufw status
```

If the result is:

```text
Status: inactive
```

no additional action is required.

## 2. Disable UFW If Required

If UFW is active and host-level firewalling is not being used because firewall rules are managed by the external network infrastructure, disable UFW:

```bash
sudo ufw disable
```

Verify:

```bash
sudo ufw status
```

Expected:

```text
Status: inactive
```

## Note

The following AlmaLinux command is **not used on Ubuntu**:

```bash
sudo systemctl disable --now firewalld
```

`firewalld` is an AlmaLinux/RHEL-oriented firewall service, while Ubuntu commonly uses UFW for host-level firewall management.

Firewall configuration should be applied consistently according to the organization's network security policy.

## Result

The Ubuntu Kubernetes nodes do not rely on an active host-level UFW firewall when network-level firewall controls are used for the Kubernetes environment.

Required Kubernetes network access is therefore controlled by the surrounding network infrastructure and its firewall policies.
